\section{Introduction}

When a software vulnerability is disclosed, it receives a CVE identifier and a short text description.
The description alone does not tell a security team how urgently to act.
For that, teams rely on structured \emph{enrichment}: a CVSS v3.1 vector that records how the flaw is exploited and what it affects, the base score (0--10) and severity tier that follow from that vector, and a CWE category for the type of weakness~\citep{first2019cvss31}.
Scanners, patch managers, and incident responders sort their queues by these fields.

For most CVEs, the National Vulnerability Database (NVD) at NIST supplied this enrichment.
It has not kept pace.
A backlog formed in early 2024, and on 15 April 2026 NIST announced that it will now enrich only CVEs in CISA's Known Exploited Vulnerabilities catalog, CVEs in software the federal government uses, and critical software under Executive Order 14028.
Everything else is marked ``Lowest Priority -- not scheduled for immediate enrichment''~\citep{nist2026nvd}.
For most new CVEs, defenders now get the description and whatever score the reporting organization chose to supply.

This paper asks how well a model can fill that gap from the description alone, using only public data.
We call this task \textbf{CVE enrichment}: given only the description, predict the eight CVSS v3.1 vector components, the base score, the severity tier, and the CWE (Figure~\ref{fig:task}).
We compare TF-IDF classifiers, a small instruction-tuned language model used zero-shot, and the same model fine-tuned with LoRA.

Two design choices shape the study.
First, we split by time.
We train on CVEs from 2022--2023 and test on every usable CVE from 2024, so a model never sees the period it is scored on.
Random splits, which several public models use, can put near-duplicate descriptions from the same product and month on both sides of the split.
Second, we treat the score as something to \emph{compute}, not something to predict.
The CVSS base score and severity are fixed functions of the eight vector components.
Following \citet{elbaz2020fighting} and \citet{shahid2021cvssbert}, we predict the components and apply the CVSS formula.
We then measure what this buys over predicting the score directly, and whether a language model's own score agrees with the vector it writes.

On all \nTest{} test CVEs, the fine-tuned model is the best system on every field (Figure~\ref{fig:headline}).
It reaches \nLoRAfSev\% severity accuracy and \nLoRAfCwe\% CWE accuracy, and it predicts the exact CVSS vector for \nLoRAfVec\% of CVEs, ahead of TF-IDF logistic regression by \nDiffLRfSev{} to \nDiffLRfVec{} points.
Its scores agree with its own vectors on \nLoRAScoreCons\% of CVEs. The same model used zero-shot agrees with itself on only \nZSScoreCons\%.
Fine-tuning took \nLoraTrainHours{} hours.

\needspace{6\baselineskip}
Our contributions:\nopagebreak
\begin{itemize}
  \item \textbf{Benchmark.} A leakage-free temporal split for CVE enrichment: \nTrainVal{} training and validation CVEs from 2022--2023 and \nTest{} test CVEs from 2024, from a pinned NVD snapshot, with a CVSS calculator that reproduces all \nAll{} NVD base scores exactly.
  \item \textbf{Comparison.} Classical, zero-shot, and fine-tuned models on every enrichment field, with 95\% bootstrap confidence intervals.
  \item \textbf{Analysis.} Direct versus formula-based scoring, and the self-consistency of language-model outputs.
  \item \textbf{Release.} Code, configuration, and per-CVE predictions for every system.
\end{itemize}
